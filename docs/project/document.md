# 服务文档结构设计 (Service Doc Structure)

本文件规定 `docs/` 下每个服务说明文档的章节结构，以 `docs/openwebui.md` 为基准模板。新增服务文档时照此骨架填写，保证所有服务文档风格统一。

文档约定：正文避免使用加粗与 emoji，列表用 `- 标题：说明` 的形式，代码/变量/路径用反引号包裹。

## 章节骨架

按以下顺序组织章节：

1. `# <服务名> 部署 (Deploy)`：文档标题。
2. `## 服务简介`：这个服务是什么、解决什么问题、关键特征一句话带过（如是否依赖外部数据库）。
3. `## 部署特性`：列表逐条说明该服务的部署特点，例如轻量独立、资产内聚、多开隔离、编排方式（docker run）、与其他组件的互通方式。
4. `## 核心配置项 (settings.conf)`：列出 `init` 生成的主要变量，逐项一句话说明用途与默认值。
5. `## 备注`：只放该服务特有的注意点（如首登即管理员、数据本地化等），通用行为不要重复写。
6. `## 快速执行`：给出最短上手命令（`up` 一键，或 `init` + `start` 分步）。
7. `## 命令解释`：每条命令独立成 `###` 小节，贴出该命令实际执行的命令，便于核对行为是否合理。
8. `## 其他补充`：收尾信息，如生产环境建议、镜像版本说明等。

## 各章节要点

### 命令解释要贴真实命令

`## 命令解释` 是结构核心：每条生命周期命令（`init` / `start` / `up` / `stop` / `rm` / `purge` / `status`）单独一个 `###` 小节，正文用一句话说明它做了什么，再用代码块贴出它在 `cli.sh` 里实际执行的命令（如完整的 `docker run` 参数）。目的是让读者不看脚本也能判断底层行为是否合理。

### 服务特有 vs 通用

服务文档只写该服务特有的信息。通用的设计理念（命令规范、目录即服务、编排与配置注入方式、实例命名、委托式级联与 `--conf`/`--name` 通用参数、app 级网络组装等）统一放在 `docs/project/` 下的 `command.md` 与 `service.md`，服务文档不重复，必要时引用。
